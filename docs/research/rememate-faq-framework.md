## 3. 双语 FAQ 的内容原则

1. **一页一语，成对问题。** 中英问题不必逐字对译，但必须覆盖同一事实，共用 slug 级题序，方便以后扩题。
2. **先回答「我现在能做什么」，再解释边界。** 获客页读者多数还没账号；登录后读者卡在导入/复习。
3. **数字、开关、额度单独成「待确认」表。** FAQ 定稿前向产品确认是否对外公布具体数字。
4. **环境敏感句必须可切换。** 注册开关、是否闭测、是否收费，不能写死成永远开放或永远邀请制。
5. **内链只用稳定公开 URL。** Landing `/`、`/qa`、`/zh/qa`、配对 Blog。不要链登录后产品页做 SEO。
6. **截图用登录后真实界面，配中英各一套。** 界面语言与学习语言是两件事，截图 caption 要写清拍的是哪一种语言界面。

建议每条 FAQ 在定稿表里保留四栏：`事实` / `待确认` / `建议中文` / `建议英文`。下面各域按此精神展开。

## 4. 域 A — 导入词库 / 导入单词（重点）

### 4.1 用户真实意图

用户通常不是来问「CSV 是什么」，而是：

- 我已经有一份词表（Aisten、Anki 导出、Excel、备忘录），怎样进 RemeMate？
- 导进去会不会覆盖/弄乱我现有的词？
- 导入后要不要再审一遍？什么时候开始复习？
- 为什么上传失败 / 处理停住 / 词没出现在生词本？
- 这和「手动加一个词」「从文章抽词」「读书时点词」有何不同？

Landing 已承诺四条收词路径：「手动加入、文本抽词、CSV 导入，或在阅读时收词。」FAQ 必须与这四条对齐，并诚实写出各自限制。

### 4.2 当前产品里「导入」实际指什么

代码把「进词」拆成两条完全不同的管道：

| 管道 | 入口 | 是否先变候选词 | 是否烧导入额度 | 是否立刻进复习 |
| --- | --- | --- | --- | --- |
| 手动加词 | `/words/add` | 否，直接写 `words` | 否 | 是（`due_date=now`） |
| CSV 导入 | `/intake/import` | 是 | 是（按生成的候选词数） | 提交入库后才是 |
| 文本抽词 | `/intake/extract` | 是 | 是 | 同上 |
| 阅读收词 | `/reading` 选词 → 加入学习 | 是 | 否（阅读服务未调用 `check_import` / `record_import`） | 同上 |
| 快速加词 | `/intake/quick-add` | 是，且依赖 AI | 是（每次 1 词） | 同上 |
| 语伴/反馈采纳 | 复盘或反馈包 | 是（含 SessionPad 专用审核） | 部分路径会记 AI 用量 | 接受后入库 |

**FAQ 建议把「导入词库」默认解释为 CSV 批量导入**，同时用 1–2 题把另外几条入口分开，避免读者以为只有一种导入。

### 4.3 建议拆出的 FAQ 子问题

主路径（应优先写）：

1. RemeMate 可以从现有词表导入吗？支持什么格式？
2. 从哪里进入 CSV 导入？导入前要先做什么？
3. CSV 需要哪些列？列名可以用中文吗？
4. 空行、缺释义、重复词会怎样？
5. 上传之后为什么还要审核？怎么入库？
6. 导入后的词什么时候出现在复习里？
7. 导入失败常见原因是什么？

次路径（可写短答或链到其他域）：

8. 文本抽词和 CSV 导入有什么区别？
9. 阅读 PDF 收词算导入吗？
10. 手动加词会不会走审核？
11. 一天能导入多少词？超额怎么办？
12. 可以从 Anki / Excel / 苹果备忘录直接导入吗？

暂不单独成题（除非产品要主推）：

- 快速加词页（入口几乎不露出）
- CSV 星标列（解析认识表头，但不写入词条）

### 4.5 支持的格式与字段

**事实（解析器 `app/services/intake.py`）**

- 只走 Python `csv.DictReader`，即逗号分隔、第一行表头。
- 编码：`utf-8-sig`（允许 BOM）。非 UTF-8 直接 `CsvFormatError`，用户看到通用句「输入为空或格式不受支持」。
- 必须同时有「词」列和「释义」列，列名不区分大小写，空格/`-` 会归一成 `_`。
- 词列别名：`word` / `term` / `单词` / `词` / `词语`。
- 释义列别名：`meaning` / `definition` / `translation` / `释义` / `解释` / `定义`。
- 可选列：
  - 词性：`part_of_speech` / `part of speech` / `pos` / `词性`
  - 例句：`example` / `sentence` / `例句` / `句子`
  - 笔记：`note` / `notes` / `笔记` / `备注`
- 另有星标别名：`marked` / `is_marked` / `starred` / `favorite` / `是否标注` / `是否收藏`。**解析会读到，但候选词模型和 commit 都不写 `Word.marked`。** 当前页上提示刻意不提星标列（Backlog 已记录）。
- 页面提示原文（中文）：「必填：word、term、单词、词、词语之一，以及 meaning、definition、translation、释义、解释、定义之一。可选：词性、例句/句子、笔记。UTF-8；≤ 500 行 / 256KB。」
- 集成测试覆盖：中文表头、Aisten 风格表头（`word,definition,sentence,note`）。
- 没有模板文件下载，没有示例 CSV 挂在页面上。
- 不接受 `.xlsx`、`.tsv`、`.apkg`、`.txt` 作为专用格式。TSV 若被当成 CSV 读，表头对不上会报格式错误。

**硬上限**

- 文件 ≤ 256 KB（`INTAKE_MAX_CSV_BYTES`）。超限 flash「CSV 文件超过 256KB 限制」。
- 有效词行 ≤ 500（`INTAKE_MAX_CSV_ROWS`）。超过 500 行有效词同样走 `CsvTooLarge`，但 UI 把所有 `CsvTooLarge` 都显示成 256KB 文案——**行数超限时用户看到的是文件过大，不是行数过多。**
- 空文件、无表头、没有有效词行：`CsvFormatError` →「输入为空或格式不受支持」。

**待确认**

- 对外示例表头用哪一套：英文 `word,meaning,example,note`，中文 `单词,释义,例句,笔记`，还是同时给？
- 是否提供可下载的最小模板（设计文档写过，产品未做）。FAQ 在模板上线前只能用代码块示例，不要写「点击下载模板」。
- Aisten / Anki 是否作为「已验证兼容」对外点名。代码只验证了 Aisten 常见列名；Anki 默认导出是 tab 分隔或 `.apkg`，**不能说「支持从 Anki 一键导入」。**
- `translation` 被当成释义列：如果用户的表是「词 / 英文释义 / 中文翻译」三列，可能把英文释义吃进 meaning，中文翻译被丢掉（未知列忽略）。是否要在 FAQ 里警告「只要一列释义，且必须是你希望留下的那一列」。
- 超 500 行时 UI 文案与真实原因不一致，FAQ 若写「最多 500 行」是在补产品缺口，需产品同意。

**建议配的解释文字 / 示例**

最小可导入示例（建议同时放中英 FAQ，并标明这是示例不是下载文件）：

```csv

décollage,n.,起飞,Le décollage m'a coupé le souffle.,机场广播里听到的
```


**不能臆测的事实**

- 分隔符是否支持分号（欧陆 Excel）。当前是标准逗号 `DictReader`，未测 `;`。
- Excel 在中文 Windows 下另存 CSV 常用 ANSI/GBK，会触发编码错误。
- 多词义（同一词多行或 meaning 里用分号）导入后会不会拆成多条 Definition。当前一行一词一条候选、入库一条 Definition。
- 词形还原、阴阳性、日语读音是否在 CSV 导入时处理。导入不做词典还原。

### 4.6 空行、缺字段、重复词、错误处理

按处理阶段拆开写，FAQ 不要混成一句「系统会自动处理」。

#### 阶段 1：上传解析（不调 AI）

**事实**

- 完全空行、或词列为空的行：**静默跳过**，不报错。
- 有词、释义为空：保留为有效行。后续交给 AI 补全；AI 不可用时用空释义兜底进候选。
- 缺必填表头（没有词列或没有释义列）：整文件拒绝，不建 `intake_source`。
- 只有表头没有有效词行：拒绝，「CSV 没有有效词行」（对用户折叠进通用格式错误）。
- 未知列名：忽略。
- 同一文件里词重复：解析阶段不去重，会生成多条 segment / 候选。
- 此阶段不检查是否已在生词本里。

#### 阶段 2：SSE 处理（可能调 AI）

**事实**

- 上传成功后跳到 `/intake/<id>/processing`，前端 `EventSource` 连 `/intake/<id>/process`。
- CSV 每批 20 行做归一化：补词性/释义/例句；已有字段尽量保留；`meaning` 按用户的**反馈语言**重写（设置里的「讲解语言」，不是界面语言）。
- AI 不可用或返回空：用 CSV 原始列值兜底，任务仍标 `done`，不把整次导入判失败。测试 `test_csv_ai_down_imports_raw_rows` 锁定此行为。
- 原文 `note` 在 LLM 漏掉时会从原始行合并回去。
- 额度在处理前检查：今日剩余导入额度为 0 则 source 标 `error`，提示今日额度用完。
- 若额度只够一部分：CSV 只处理 `min(行数, 剩余额度)` 行，多出的行本轮不会变成候选。
- 文本抽词与 CSV 不同：抽词在 AI 不可用时整单失败，不兜底。
- 处理页被中断可重开；`status=processing` 时会清掉旧候选再跑，避免重复累积。已 `done` 则直接返回完成。

#### 阶段 3：候选审核

**事实**

- 每条候选可改词、词性、释义、例句，然后「接受」或「忽略」。
- 若该语言生词本已有同一词（去空白、小写后相同），卡片上黄字「该词表已有此词」。
- 筛选：全部 / 待审核 / 已接受 / 已忽略。
- 「一键入库」在「全部」视图：先接受所有 pending，再 commit。
- 「提交入库（已接受的）」在「待审核」视图：只 commit 已接受的，不动 pending。
- 「一键清理」删除已忽略和已接受的候选（不可恢复），不删除已经进生词本的词。
- 审核中途离开，状态已写入数据库，可回来继续。

#### 阶段 4：commit 入库

**事实**

- 只写入 `status=accepted` 的候选。
- 同语言隐式词表内，词身份 = `strip + lower`。已存在则**静默跳过**，不报错、不合并新释义，只把候选挂到已有 `word_id`。
- 新词：`due_date=现在`，`interval=1`，`ease=2.5`，`reps=0`，`lapses=0`，立即进入该语言复习队列。
- 有释义/词性/例句/笔记才建 `Definition`；全空则只建光秃词条。
- 成功后 flash「已入库 {count} 个词」，并切到该语言，跳转生词本。`count` 是新建词数，不含被去重跳过的。
- 不把 CSV 文件存盘，只保留解析后的 segment JSON。

**待确认**

- 静默去重是否要在 FAQ 里说成「不会覆盖已有词的释义」。建议说，但这是产品承诺，需点头。
- 同一 CSV 内重复词：审核时会看到多张卡，入库只留先成功的那条。对外要不要建议用户先在表格里去重。
- 大小写/重音：`café` 与 `Cafe` 是否视为同一词，取决于 Unicode lower，未做重音折叠。不要写「所有拼写变体都会合并」。
- 行数超限却提示 256KB：FAQ 排查清单里要不要写真实原因。这是产品债，写出去等于公开 bug。

**建议配图**

- 处理中进度条（「已处理 20 / 80」）。
- 候选卡：含「该词表已有此词」警告的一条。
- 审核页顶部「一键入库 / 一键清理」。
- 入库后生词本列表，新词出现在当前语言下。

**建议文案方向（重复词）**

> 生词本里已经有的词不会被覆盖。审核时会标出来；入库时自动跳过，只把真正的新词加进去。

**建议文案方向（空行）**

> 空行和没有词的行会被跳过。只要表头正确、至少有一行词，其余空行不必手动删干净。

### 4.7 导入后如何复习

**事实**

- 入库后的新词 `due_date` 为当前时间，属于「待复习」，不是「明天才出现」。
- 复习队列按**当前主攻语言**切。导入时会 `set_current_language` 到该 CSV 的语言，所以通常导入完回到首页就能刷到这些词。
- 若用户随后又切到另一种语言，这些词不会出现在首页，直到切回导入时的语言。
- 首页词卡 = 复习词卡：显示词形，点开释义/例句/笔记，三按钮「没记住 / 有点模糊 / 秒记起」。
- 星标、编辑、朗读在词卡工具条；CSV 星标列不会预打星。
- 导入本身不生成复习小故事。小故事是当天复习满一定条件后的可选项。

**待确认**

- 是否对外说「导入后会立刻进入今天的复习」。这与部分 SRS 产品「新词先学习再复习」不同，需要产品确认这个差异要强调还是淡化。
- 大批量导入（例如 200 词全 due）会不会把当天复习队列撑爆。代码没有「新词学习上限」。FAQ 不宜承诺「会自动把新词摊到后面几天」。

**建议配图**

- 导入成功 flash + 生词本。
- 回到首页，一张刚导入的词出现在复习卡上。
- 顶栏语言切换器停在导入所用语言。

**建议文案方向**

> 点「一键入库」或「提交入库」之后，新词会进入你刚刚选择的那种语言的生词本，并且马上可以复习。打开首页，确认右上角语言和导入时一致。

### 4.8 常见失败排查（建议做成 FAQ 长答或子列表）

| 用户看到的现象 | 已证实原因 | FAQ 可写的排查 | 不能臆测 |
| --- | --- | --- | --- |
| 「请选择语言并上传 CSV」 | 没选语言或没选文件 | 先设置学习语言，再选 `.csv` | — |
| 「先在设置里选择正在学的语言」 | `learning_languages` 为空 | 去设置勾选语言 | — |
| 「输入为空或格式不受支持」 | 非 UTF-8、无表头、缺词/释义列、无有效词行、空文件 | 另存 UTF-8 CSV；第一行必须是表头；必须有词列和释义列 | 无法从这条 flash 区分四种原因 |
| 「CSV 文件超过 256KB 限制」 | 文件 >256KB **或** 有效行 >500 | 拆成多个文件；检查是否其实是行数过多 | 对外是否承认文案不精确 |
| 处理中停在「连接中…」或「处理中断，请重试」 | SSE 断开、代理超时、刷新 | 不要关页；失败后重新打开处理页（幂等） | 用户网络/nginx 超时具体秒数 |
| 「AI 暂不可用」 | 抽词失败，或处理事件被改写成该句 | CSV 通常会用原表兜底；抽词需要重试 | 重试要等多久 |
| 「今日导入额度已用完」 | `imports_today >= limit` | 等用户时区午夜重置；页顶能看到已用/上限 | 是否建议联系管理员加额度 |
| 上传成功但生词本没有词 | 只处理完、没点入库；或全部被去重；或看错语言 | 去候选页入库；看当前语言；看「已入库 N 个」是否为 0 | — |
| 词在了但释义是英文/错语 | 反馈语言不是用户期望；或 AI 按反馈语言重写了 meaning | 设置里改「讲解语言」后再导入 | AI 是否保证 100% 用该语言 |
| Excel 打开正常、网站报错 | 本地编码/分号分隔/xls | 用「CSV UTF-8」另存 | 每一种 Excel 版本的菜单路径 |
| 星标没带过来 | 列被解析但不入库 | 入库后在生词本或复习卡上手动标 | 未来会不会支持 |
| 想导 Anki | 无 apkg/TSV 导入器 | 先在 Anki 导出为逗号 CSV，并改成支持的表头 | 某张 Anki note type 的字段能否自动对上 |

**建议配图**

- 错误 flash 条各一张（至少：格式不受支持、超过 256KB、额度用完、未选语言）。
- 候选页空列表 vs 生词本空态，帮助区分「还没入库」和「看错语言」。

### 4.9 导入域需要向产品确认的资料清单

1. 生产是否公布具体导入额度（200 / 2000），以及自带 key 对用户是否存在。
2. 是否提供官方 CSV 模板及下载位置。
3. 对外兼容声明：只说「CSV」，还是点名 Aisten；Anki 只写「需先转 CSV」还是不提。
4. 重复词策略的对外句子：跳过且不合并释义，是否即为最终产品规则。
5. 新词立即 due 是否为期望体验；大批量导入有无「先别全挤进今天」的产品计划。
6. 500 行与 256KB 的用户文案是否在 FAQ 发布前修。
7. 快速加词是否写入 FAQ。
8. 星标列：明确写「不支持」还是完全不提。
9. 反馈语言改写 meaning：对外解释成「帮助你用母语看懂」，还是允许用户关闭归一化（后者当前没有开关）。
10. 多文件拆分导入的推荐批次（例如每次 100 行）——代码无建议，属内容政策。
11. 中英 FAQ 示例词用哪门语言（法语 `décollage` 与 Landing/测试一致，或改用更中性的词）。
12. 导入是否收集用户表格做改进；当前文件不落盘，但 segment JSON 在库里——对外隐私句需法务/产品点头。

## 5. 域 B — 遇到真实词之后的记录与整理

### 5.1 用户真实意图

「我刚在对话/字幕/书里碰到一个词，怎么收下并整理成以后能复习的东西？」这是 Landing 主叙事，也是和「导入一份旧词表」不同的故事。

### 5.2 建议拆出的子问题

1. 现场碰到一个词，最快怎么记下来？
2. 手动加词要填哪些字段？AI 填充是什么？
3. 为什么有的词要先审核，有的直接进生词本？
4. 一个词可以有多个释义吗？
5. 怎样改词、删词、打星标？
6. 生词本是按语言分开的吗？我要不要自己建词表？

### 5.3 事实

- **词表对用户是隐式的。** 设置里勾选学习语言时，系统按语言 `get_or_create_language_list`。界面不让用户「新建词表」。
- 支持的学习语言代码：`fr` `en` `ja` `de` `es` `ru` `zh`。
- **手动加词 `/words/add`**：选语言、填词、多条释义（词性/释义/例句/笔记）。可选「AI 填充」整词，或单条「生成例句」「生成笔记」。直接入库，不经候选页。
- 词最长 200 字；每条释义至少要有词性或释义。
- 词性选项：`n. v. adj. adv. prep. conj. pron. interj. num. art. phr.` 以及空。
- 编辑 `/words/<id>/edit`：可改词和多释义。改成与同语言已有词冲突会报「词已存在」。
- 删除：生词本/详情里可删单个词（会删该词复习日志）。
- 星标：复习卡和生词本可切换；列表可筛「只看已标记」。
- 生词本排序：到期（默认）/ 最近 / 遗忘次数；前端还有搜索框。
- 文本抽词：粘贴 ≤8000 字，最多抽 50 个生词，AI 选「可能陌生、非极高频、非专有名词/数字」的词，然后进候选审核。
- 阅读收词：上传 PDF，选中词查本地词典，点「加入学习」变候选；若生词本已有该词，会提示已存在。
- 语伴复盘/反馈包也可以把表达收成候选（见伙伴域）。

**手动加词遇到重复词：** `add_word` 发现同语言已有相同身份的词时，**直接返回已有词，不合并新释义**，前端仍可能显示「已加」。这与编辑时的显式报错不一致。

### 5.4 待确认

- 重复手加是「算成功」还是应对用户说「已经有了，请去编辑」？当前实现偏前者，FAQ 若按后者写会与产品不符。
- AI 填充用的是系统 LLM，是否消耗写作额度或导入额度？手动加词的 fill/example/note 走 `task="general"`，不走导入计数；是否消耗「隐藏的 token 日限额」不要对外乱讲。
- 抽词「最多 50」是否写进 FAQ（页面 placeholder 已写）。
- 用户有没有「合并两条重复词」的产品计划。没有就不要承诺。

### 5.5 建议配图 / 示例

- 手动加词页：语言 + 词 + 两条释义 + AI 填充按钮。
- 生词本四入口卡（和导入域复用）。
- 词编辑页。
- 文本抽词页字数计数（0/8000）。
- 示例故事：「地铁广播里的 décollage → 手动加词，补机场语境笔记」。

### 5.6 不能臆测

- 离线/无网能否加词（Web 应用，未做 PWA 离线库）。
- 语音输入收词（只有朗读，没有语音加词）。
- 浏览器划词插件、油猴脚本。
- 多设备实时同步的具体延迟（单账号 Web，未宣称离线同步协议）。

## 6. 域 C — 复习 / 记忆

### 6.1 用户真实意图

- 今天该背什么？为什么首页只有一张词？
- 三个按钮分别意味着什么、下次什么时候再见到？
- 没记住会不会立刻又弹出来？
- 小故事是什么？必须生成吗？
- 统计里的数字怎么读？

### 6.2 建议拆出的子问题

1. 登录之后为什么直接看到一张词卡？
2. 三个复习按钮有什么区别？
3. 点「没记住」之后这个词去哪了？
4. 怎样回到上一张词？
5. 「今日复习小故事」何时出现？不生成会怎样？
6. 统计页的「待复习」包含过期的词吗？
7. 可以用手机通知来复习吗？

### 6.3 事实

- 登录后首页渲染当前语言下一张 due 词（`due_date <= now`），不是仪表盘。
- 未选学习语言：空态引导去设置。
- 无 due 词：完成态「今日复习完成，没有到期的词了。」
- 三按钮映射 SM-2：`forgot→q=2`，`fuzzy→q=3`，`easy→q=5`。界面文案：没记住 / 有点模糊 / 秒记起。
- 没记住：`reps` 归零，`lapses+1`，`due_date = now + 10 分钟`，避免立刻再抽到同一张。界面有 lapse 提示。
- `fuzzy`：通过但偏难；`easy`：通过且容易。间隔按 SM-2（首遍 1 天，第二遍 6 天，之后 `interval * ease`）。
- 评分带 `expected_due_at` 版本；过期/重复提交不重复改调度。
- 可返回上一张（session 记 `review_previous_word_id`），上一张视图不带评分按钮。
- 词卡可朗读（浏览器语音）、编辑、打星。释义默认折叠。
- 复习小故事：当天该语言复习满 **10** 张才出现入口；若弱项（模糊/没记住）多于 5，文案走加强版。选最多 5 个目标词生成短文。失败不影响复习记录。可从故事跳去造句。
- `/stats`：当前语言的总数/待复习/词表；今日已复习和热力图跨语言合计。
- Bark：设置里可填 Bark URL，开关「复习提醒 / 每日摘要 / 导入完成」。通知里的 token 链打开 `/bark/review/<token>` 单卡评分，不需登录会话。

### 6.4 待确认

- 是否对外说出「SM-2」这个名字，还是只描述三个按钮的结果。
- 10 分钟、1 天、6 天这些数字是否写进 FAQ。写了就变成用户可依赖的契约。
- 小故事的 10 张 / 5 个弱项阈值是否公布。
- Bark 是否作为「官方通知方式」推广，还是写成进阶、仅 iOS 用户。
- 有没有邮件复习提醒。当前账号邮件只用于验证和重置密码。
- FSRS：代码注释说 P2 再切。不要写「使用 FSRS」。

### 6.5 建议配图 / 示例

- 首页一张词卡，释义折叠 + 三按钮。
- 点开释义后的样子。
- 完成后空态。
- 小故事回执（目标词锚点）。
- 统计页「待复习」而不是「今日到期」（文案已改过，避免旧截图）。

### 6.6 不能臆测

- 算法是否「比 Anki 更准」。
- 记忆保持率、几天能记住。
- 是否有学习模式 vs 复习模式的双队列。
- 是否支持自定义按钮数或自己调 ease。

## 7. 域 D — 阅读或上下文

### 7.1 用户真实意图

- 能不能把正在读的材料变成词的出处？
- 支持什么文件？扫描件行不行？
- 点词后词典不准怎么办？
- 读到一半关掉，位置还在吗？

### 7.2 建议拆出的子问题

1. 阅读收词怎么用？
2. 只支持 PDF 吗？电子书、网页、字幕呢？
3. 为什么有的 PDF 传不上去？
4. 查词用的是什么词典？查不到还能加吗？
5. 加入学习之后要去哪里审核？
6. 阅读进度会保存吗？

### 7.3 事实

- 入口：词库 → 阅读收词 `/reading`；生词本入口卡「上传 PDF，阅读时把遇到的词加入候选词」。
- 书架按**当前学习语言**列出材料。
- 上传：仅 `.pdf`。语言必须在阅读词典支持集 `zh en ja fr` 内（比学习语言少 `de es ru`）。
- 解析纯文本 PDF。无文字（扫描/图片型）→「OCR 不支持」类提示。解析失败、质量检查失败（过短、乱码比例高、中日文缺标点）会拒绝或跳过该分片。
- 过长 PDF 可能被拆成多份，并 flash 拆分数量。
- 配置上限（默认可被环境覆盖）：上传请求 31MB 外壳；阅读专用默认约 8MB / 80 页 / 25 万字符。parser 另有更大的内部默认，路由用的是阅读配置。
- 阅读器：纯文本，不是排版还原的 PDF 阅读器。
- 选词查**本地词典**（`DICTIONARY_DATA_DIR`）。在线 API 已关闭。
- 查不到仍显示卡片，可「加入学习」。已在生词本则提示已有。
- 加入后进该文档关联的 intake 候选；阅读器可回链「返回书本」。候选上能看到 PDF 原文语境。
- 滚动位置会 POST 保存。
- 可删除文档（及 lookup）。
- 已知词会参与阅读器高亮（把该语言生词本词形交给前端）。

### 7.4 待确认

- 对外是否明确说「不是完整阅读器，只是收词用的文本阅读」。策略文档的 canonical 英文是 *Collect from reading*。
- 德/西/俄为什么不能阅读收词：是词典数据范围，还是产品范围。FAQ 不要编原因。
- OCR 是否在路线图。当前必须写「不支持扫描件」，不要写「即将支持」。
- 本地词典覆盖范围、版权、释义语言。查到的释义可能不是用户反馈语言。
- 阅读收词是否应在 FAQ 里写成「不占每日导入额度」。代码如此，但是否对外强调由产品定。

### 7.5 建议配图 / 示例

- 书架列表 + 待审核候选计数。
- 上传页：语言 + 仅 PDF。
- 阅读器选中一词后的 lookup 卡（词典命中 / 未命中各一张）。
- 从候选页「返回书本」。

### 7.6 不能臆测

- 支持 epub/mobi/网页剪藏。
- 左右分栏对照、分页排版、图片内文字。
- 词典来源名称（除非产品批准点名数据包）。
- 「和 Lute 一样」——内部有 Lute MVP 设计文档，不是对外品牌。

## 8. 域 E — 写作 / 反馈

### 8.1 用户真实意图

- 怎样把记住的词用出来？
- AI 会改我的句子吗？改完会不会自动保存？
- 为什么写不了了（额度）？
- 公开到广场安全吗？
- 语伴给我的纠正怎么变成我的词？

### 8.2 建议拆出的子问题

1. 造句和三行日记有什么不同？
2. 批改之后必须保存吗？
3. 每天能写多少？
4. 什么是广场？谁能看见？
5. 语言伙伴的复盘和反馈包是什么？
6. 为什么提示「句子语言不匹配」？

### 8.3 事实

- `/write` 两种模式：造句（对着一个目标词，≤140 字）；三行日记（3 行 × ≤100 字，带随机提示）。
- 流程：提交只批改，结果放在签名 session；用户显式保存才入库。刷新不会重放 POST。可丢弃。
- 批改用设置里的**讲解语言**写 feedback/translation。
- 目标词未使用、不完整、有 errors 会在结果里体现。NSFW 标记进 session，防篡改。
- AI 不可用：降级结果，不入库。
- 额度：按成功提交批改次数计，写错重试也计。系统 key 每天 3 句；自带 key 每天 20 句。按用户时区午夜重置。
- 设置页**没有**填写自己 API key 的表单。超额文案仍说「可在设置页配置自己的 key」——与 UI 不符。
- 历史 `/write/history` 可发布/取消发布。发布后出现在 `/square`，可按语言和类型（句子/日记）筛选，可点赞。作者可撤回。
- 复习小故事可 handoff 到造句，带着指定目标词。
- 语言伙伴：私人关系，不是公开社交。可记复盘（帮自己记 / 帮对方记），生成总结时「私人伙伴笔记不会发送给 AI」。绑定账号后可发反馈包；对方可致谢、把条目收成候选词。邀请不泄露对方是否已注册。

### 8.4 待确认

- 3 / 20 的额度是否对外公布。
- 「自带 key」对外如何解释；在设置项上线前，FAQ **不要**教用户去设置页填 key。
- 广场是否要在获客 FAQ 里出现。SEO 计划说首版只服务获客、不服务登录后产品；广场偏登录后，可放到次要题或登录后帮助。
- 发布到广场的内容是否会被搜索引擎收录。产品页默认 `noindex`，`/square` 在 robots Disallow 里。
- SessionPad 在对外文案中叫「语言伙伴 / 复盘 / 反馈」，不要叫 SessionPad，除非对内帮助文档。

### 8.5 建议配图 / 示例

- 造句页：目标词 + 输入框 + 今日额度。
- 批改结果 +「保存 / 丢弃」，强调不会自动入库。
- 日记三行。
- 广场一条已发布句子（若决定写这题）。
- 伙伴复盘表单里的隐私提示原文。

### 8.6 不能臆测

- AI 批改准确率、是否有人工老师。
- 会不会用用户句子训练模型。
- 广场审核/举报流程（路由未实现举报）。
- 作文批改、口语打分、发音评测。

## 9. 域 F — 账号与隐私

### 9.1 用户真实意图

- 我的词库别人能看见吗？
- 广场和语伴分别暴露什么？
- 你们用邮件和 AI 时会寄出我的哪些内容？
- 怎样改显示名和密码？

### 9.2 建议拆出的子问题

1. 哪些内容是私密的，哪些会被别人看到？
2. 语言伙伴能看见我的生词本吗？
3. AI 会看到我的私人笔记吗？
4. 如何修改显示名和密码？
5. 有没有隐私政策？

### 9.3 事实

- 词库、阅读材料、候选词、复盘、未发布写作均挂 `user_id`，服务层显式传用户，数据库有 RLS。
- 设置可改显示名（1–100 字）和密码（需当前密码，新密码 8–128 字）。
- 登录失败不区分「用户不存在 / 密码错误」；连续 5 次失败锁定 15 分钟，对外仍是同一句「邮箱或密码错误」。
- 注册/忘记密码对外统一响应，不透露邮箱是否已注册。
- 伙伴邀请、互邀确认页有明确隐私微文案：不泄露注册与否；确认后双方看不到对方词库或历史复盘；互邀只预填昵称和语言方向。
- 复盘总结：私人伙伴笔记不发送给 AI。
- 广场：仅用户主动发布的句子/日记。
- 公开站点无独立隐私政策或条款页。
- 复习小故事事件按「privacy-safe」设计，不是把全文日志公开。
- Admin 可建号，不能在 UI 里删号或导出用户数据包。

### 9.4 待确认

- 是否在 FAQ 发布前补一页公开隐私说明；若无，FAQ 只能写产品行为，不能假装有法律文本。
- 数据存哪里、备份多久、闭测运营方是谁。
- CSV segment、阅读正文、lookup 记录的保留期限。
- Discord 社群（Landing 有链接）与账号数据的关系：社群不是产品内账号系统。
- 是否向监管地区做 GDPR/个保法声明。没有法务文本就不要用这些词。

### 9.5 建议配图 / 示例

- 设置页账号区块（显示名、密码）。
- 伙伴邀请框下的灰色隐私说明（可直接引用已定稿翻译）。
- 对照表（建议做成 FAQ 内表格，而非长文）：

| 内容 | 默认可见范围 |
| --- | --- |
| 生词本、复习、阅读、未发布写作 | 仅自己 |
| 复盘与私人备注 | 仅自己；绑定伙伴也看不到你的历史复盘 |
| 你发送的反馈包条目 | 指定伙伴 |
| 主动发布的句子/日记 | 登录用户的广场 |
| Landing / Q&A / Blog | 公开网页 |

### 9.6 不能臆测

- 「我们绝不出售数据」。
- 端到端加密（没有）。
- 员工是否能读用户词库（有 dispatch/admin/bypass 角色，不能对用户说「谁也看不到」）。
- 删除账号后的残留备份。

## 10. 域 G — 语言设置

### 10.1 用户真实意图

用户常把三件事混成一件：「我把语言改成英语，为什么词还是法语？为什么 AI 还用中文解释？」

### 10.2 建议拆出的子问题

1. 界面语言、正在学的语言、讲解语言有什么区别？
2. 怎样切换正在复习的语言？
3. 怎样一次学几门语言？
4. 时区会影响什么？
5. Landing 上的「中 / EN」和登录后的界面语言是一回事吗？

### 10.3 事实

产品明确拆开三种语言（`docs/strategy/2026-07-12-app-i18n.md` + 设置页）：

| 名称 | 存什么 | 控制什么 | 怎么改 |
| --- | --- | --- | --- |
| 界面语言 `ui_locale` | `zh` / `en` | 导航、按钮、系统提示 | 顶栏 `中/EN`，或设置；登录后写入 `user_settings`；未登录看 session，再看浏览器 `Accept-Language`，默认中文 |
| 正在学 / 当前主攻 | 多选集合 + 当前一个 | 复习、生词本、阅读书架、写作目标语、导入默认语言 | 设置里多选「在学哪几种」；顶栏旗帜切换当前主攻（`POST /language/switch`） |
| 讲解 / 反馈语言 | `zh` / `fr` / `en` | AI 释义、批改、抽词 meaning | 仅设置页 |

- 改其中一项不会改另外两项。
- 顶栏语言切换器只列出已勾选的学习语言。
- 时区选项：上海、巴黎、UTC、东京、纽约、洛杉矶。影响额度重置「今天」、统计「今日」、任务卡（即使任务卡未展示）的日期切割。
- Landing 的中英切换写在 `localStorage.landingLang`，**只影响这一张营销页**，不会改登录后界面语言。
- 公开 Q&A/Blog 是不同 URL，不是页内切换。

### 10.4 待确认

- 对外中文把 `feedback_language` 叫「讲解语言」「母语」还是「AI 说明语言」。设置键是 `settings.feedback_language`；策略表曾用「母语」，但用户母语完全可以不是讲解语言。
- 是否解释「为什么讲解语言只有中/英/法」。
- 默认时区、默认讲解语言对新注册用户的值（开放注册计划写：显示名用邮箱前缀，时区与学习语言沿用现有默认）。需从 `provisioning` 核对后才能写进 FAQ。

### 10.5 建议配图 / 示例

- 设置页三块并排：界面语言、正在学、讲解语言。
- 顶栏：界面 `EN` 按钮 vs 学习语言旗帜，同一张图上标两个箭头。
- 一句话示例：「界面英文 + 正在学法语 + 用中文看释义」。

### 10.6 不能臆测

- 即将支持更多界面语言。
- 按浏览器自动切换学习语言（不会）。
- Landing 语言选择会带进注册后的界面（两套存储，未自动打通）。

## 11. 域 H — 注册与登录

### 11.1 用户真实意图

- 现在能自己注册吗？
- 为什么只填邮箱？邮件没到怎么办？
- 验证链接过期了？
- 忘记密码会不会暴露我有没有账号？

### 11.2 建议拆出的子问题

1. 如何创建账号？（**必须按环境分支写**）
2. 注册只需要邮箱吗？然后要做什么？
3. 没收到验证邮件怎么办？
4. 如何登录 / 退出？
5. 忘记密码怎么处理？
6. 为什么提示「邮箱或密码错误」却不说是哪一个？

### 11.3 事实

注册流程（代码已实现，**默认关闭**）：

1. `OPEN_REGISTRATION_ENABLED` 缺省/`false`：`/register` 返回 404，Landing 与登录页无注册入口。
2. 打开时：注册页只填邮箱 → 统一 flash「如果该邮箱可用，我们会发送相关邮件」→ 24 小时单次验证链接 → 原子建号并登录 → 强制设至少 8 位密码，设完前只能设密和登出。
3. 显示名暂用邮箱前缀。
4. 已发出的验证链接在关闸后、有效期内仍可建号。
5. 忘记密码始终可用（与注册开关无关）：统一响应，1 小时单次链接，重设后登录。不撤销其他设备 cookie。
6. 邮件限频默认：单邮箱 3 次/分钟且 5 次/小时，单 IP 20 次/小时，全局 200 封/天。
7. 无验证码。
8. 管理员仍可用 `/admin` 或 CLI 邀请建号（闭测路径）。
9. 正式环境部署文档要求生产默认保持注册关闭，开启需单独批准。当前 handoff：SEO1 正式环境未部署；开放注册亦不自动等于已对公众开放。

登录：邮箱小写化；锁定策略见账号域。`next` 只接受同域相对路径。

### 11.4 待确认（此域阻塞项最多）

1. **FAQ 发布当天，生产注册是开还是关？** 两套正文必须都准备，发布时只上其中一套，或写「若页面没有注册按钮，说明目前仍是邀请/闭测」。
2. 是否收费、是否「free account」。Landing 在开关打开时写 “Create a free account”；开关关闭时不承诺开放注册。
3. 邮件进垃圾箱、企业邮箱拦截的官方建议（查垃圾箱、加发件人）——发件人域名取决于 Resend 配置，FAQ 不能杜撰 From 地址。
4. 未收到邮件是否等于邮箱已注册。产品故意不透露，FAQ 必须保持同一口径。
5. 闭测邀请怎么申请：Discord？邮件？不写「填表即通过」。
6. 密码是否还有复杂度规则（当前只强制长度 ≥8）。

### 11.5 建议配图 / 示例

- **开关关闭：** Landing 主 CTA 是「登录」，无注册按钮。
- **开关打开：** Landing + 登录页底部「创建账号」+ 注册页只含邮箱。
- 设密页。
- 忘记密码页。

不要用开发环境截图假装生产已开放注册。

### 11.6 不能臆测

- 「向所有人开放」。
- OAuth / 通行密钥 / 手机号登录。
- 多因素认证。
- 验证邮件一定在 N 分钟内到达。

## 12. 域 I — 数据导出或删除

### 12.1 用户真实意图

- 我想带走词库（去 Anki 或其他工具）。
- 我想删掉某个词 / 某本书 / 整个账号。
- 法规或个人安全要求「删除我的数据」。

### 12.2 建议拆出的子问题

1. 可以导出我的生词本吗？
2. 如何删除单个词或一篇阅读材料？
3. 如何删除整个账号和全部数据？

### 12.3 事实

| 能力 | 现状 |
| --- | --- |
| 用户自助导出 CSV/JSON/Anki | **不存在**路由、按钮、CLI 用户命令 |
| 删除单个词 | 存在（生词本/编辑相关删除） |
| 删除一篇阅读材料 | 存在 |
| 清理候选词（已接受/已忽略） | 存在；不删已入库的词 |
| 删除某一语言的整本生词本 | 服务层有 `delete_word_list`，**无对应用户路由**；词表是隐式的，界面只提供删单个词 |
| 取消发布广场内容 | 存在 |
| 用户自助注销账号 | **不存在** |
| 管理员一键删用户及级联数据 | 管理页只建号列最近 20 人，无删除 |
| 测试用 `_wipe` | 仅测试库，与用户无关 |

因此：「导出」「删除账号」在 FAQ 里必须标成 **功能不存在 / 待确认对外口径**，不能写成「请到设置里导出」。

### 12.4 待确认

- 闭测阶段若有用户要求删号，走哪条人工流程（邮件给谁、处理时限）。
- 是否计划做导出；未上线前 FAQ 建议：「目前不能自助导出；需要的话请通过社群/运营联系。」——须产品给出联系方式。
- 删词是否级联删除造句历史里对该词的引用，观感如何。
- 备份保留政策。

### 12.5 建议配图 / 示例

- 只拍「删除一个词」「删除一篇 PDF」的确认动作，证明局部删除存在。
- 不要做假的「导出」按钮示意图。

### 12.6 建议文案方向（待产品批准）

> 你可以删除单个词或一篇阅读材料。目前还不能在设置里下载全部数据或注销账号。如果你需要我们协助处理账号，请通过 [待确认渠道] 联系。

在渠道未定时，宁可不上这道题，也不要写「请联系 support@…」这种臆造地址。
