## 一、Bug 清单（审查发现）

### [P1] `flask reset-quota` 漏重置 `corrections_today` 和 `imports_today`
- 位置：`app/services/provisioning.py`（`reset_quota` 函数）
- 现象：管理员用 `flask reset-quota --email xxx` 重置用户额度时，只清零了 `tokens_used_today` 和 `bonus_tokens_today`，**漏了 `corrections_today` 和 `imports_today`**。用户造句/导入额度不会被重置，仍然被锁在上限。
- 复现：用户造句用完 3 句额度 → 管理员跑 `flask reset-quota --email xxx` → 用户刷新造句页仍显示"今日造句额度已用完（3/3）"。
- 影响：闭测运营场景高概率遇到——朋友测试时额度用完，管理员想重置让他们继续测，但重置无效。
- 根因：`_maybe_reset`（自然重置）清零全部 4 个计数器，但 `reset_quota`（管理员手动重置）只清了 2 个，两者不一致。

### [P2] 导入流程 AI 不可用时未优雅降级（SSE 崩溃 / quick_add 500）
- 位置：`app/services/intake.py`（`_normalize_csv_batch` / `_extract_from_text` / `_enrich_word`）；`app/blueprints/intake/routes.py`（`process_stream` / `quick_add`）
- 现象：这三个函数直接调 `llm.chat()`，没有 try/except 捕获 `AllProvidersDown`。当 LLM 全挂时：
  - CSV/抽词的 SSE 生成器会抛异常崩溃，前端 EventSource 断开，用户只看到"连接断开"不知道原因
  - quick_add 路由会返回 500 错误页，不是友好提示
- 复现：不配 API key（`flask doctor` 报 WARN LLM correction）→ 登录 → 进加词中心 quick_add 提交一个词 → 500 错误。
- 影响：闭测时如果 API key 过期/额度用完，导入和快速加词整个不可用且无提示。造句流程有降级（`correction.py` 捕获 `AllProvidersDown` 返回 degraded），但导入流程没有对齐。

### [P3] 日语（`ja`）造句缺脚本级语言守卫
- 位置：`app/services/writing.py`（`_validate_sentence_language`）
- 现象：`_validate_sentence_language` 对 `language_code == "ja"` 既不检查是否含 CJK/Kana（因为 `ja` 不在 `{"fr","en","de","es","ru"}` 集合），也不检查是否不含 CJK（因为只检查 `== "zh"`）。用户可以用法语造句提交日语造句练习，绕过 cheap guard。
- 影响：低——AI 批改仍会处理真实语言判断，这只是 cheap guard 防烧 token 的第一道关。日语是支持的 7 语言之一，漏了 guard 不一致。

### [P3] admin 创建账号后端不校验 email 格式
- 位置：`app/services/provisioning.py`（`normalize_email` / `create_user_with_defaults`）
- 现象：`normalize_email` 只做 `strip().lower()`，不校验 email 格式。admin 网页表单有 `type="email"` 浏览器校验，但后端无兜底——curl 绕过浏览器可创建 `foo@bar` 这种无效 email 账号。
- 影响：低——闭测阶段只有 admin 能创建账号，admin 不会故意输错。但后端无兜底是不规范。

### [P2] 加词入口页覆盖全局语言字典导致 500
- 位置：`app/blueprints/intake/routes.py`；`app/templates/intake/*.html`
- 现象：CSV 导入、文本抽词、快速加词页面把 `lang_choices` 传成了“当前用户可选语言列表”，覆盖了全局模板上下文里的“语言字典”。`base.html` 的顶部语言切换器调用 `lang_choices.get(...)` 时遇到 list 会抛 500。
- 影响：中——用户从快速加词失败提示重定向回来，或直接打开加词入口页，都可能看到 500。

### [P3] `OutputEntry.upvote_count` 列定义但从未使用（死代码）
- 位置：`app/models/output.py:23`
- 现象：`upvote_count` 列被定义为"夯票冗余缓存"，但 `square.py` 用实时 `func.count(SentenceUpvote.id)` 查询，`upvote_entry` 也不更新此列。全代码库无写入/读取点。
- 影响：无功能影响，只是死代码 + 误导。**本轮未修**（避免迁移，留待后续清理）。

## 二、已修清单

### 修复 1：P1 `reset_quota` 补全计数器重置
- 文件：`app/services/provisioning.py`
- 改动：`reset_quota` 函数补 `quota.corrections_today = 0` 和 `quota.imports_today = 0`，对齐 `_maybe_reset` 的 4 个计数器全清零。
- 验证：全量测试 159 passed。

### 修复 2：P2 导入流程 AI 不可用优雅降级
- 文件：`app/services/intake.py`
- 改动：
  - `_enrich_word` / `_extract_from_text` / `_normalize_csv_batch`：try/except 捕获 `llm.AllProvidersDown`，返回 `({}, None)` / `([], None)`，不抛异常。
  - `process_source`：text_extract 和 csv 分支检查 `res is None`，设 source status=error，yield `{"type":"error","message":"AI 暂不可用，请稍后重试"}` 后 return，SSE 不崩溃。
  - `quick_add`：检查 `res is None`，抛 `CsvFormatError("AI 暂不可用，请稍后重试")`，路由已有 `except CsvFormatError` 会 flash 友好提示，不返回 500。
- 验证：全量测试 159 passed。

### 修复 3：P3 日语造句补语言守卫
- 文件：`app/services/writing.py`
- 改动：`_validate_sentence_language` 把 `if language_code == "zh"` 改为 `if language_code in {"zh", "ja"}`，日语造句也要求含 CJK/Kana。
- 验证：全量测试 159 passed。

### 修复 4：P3 admin 创建账号补 email 格式校验
- 文件：`app/services/provisioning.py`
- 改动：
  - 新增 `_EMAIL_RE = re.compile(r"^[^@\s]+@[^@\s]+\.[^@\s]+$")`。
  - `create_user_with_defaults` 里 `normalize_email` 后加 `if not _EMAIL_RE.match(email): raise ValueError("邮箱格式不正确")`。
  - CLI `create-user` 已有 `except ValueError as e: raise click.ClickException(str(e))`，admin 路由已有 `except ValueError as e: flash(str(e))`，所以两端都会显示友好错误。
- 验证：全量测试 159 passed。

### 修复 5：P2 加词入口页语言变量改名
- 文件：`app/blueprints/intake/routes.py`；`app/templates/intake/import.html`；`app/templates/intake/extract.html`；`app/templates/intake/quick_add.html`
- 改动：页面自身的语言选项改为 `available_languages`，避免覆盖 `base.html` 依赖的全局 `lang_choices` 字典。
