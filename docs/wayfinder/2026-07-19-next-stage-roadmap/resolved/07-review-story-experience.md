# 复习流程与短故事体验

## Question

普通入口、薄弱词加强提醒、生成中、失败、缓存结果和写作交接应如何出现在现有复习流程中，
既清楚又不强迫用户，也不要求用户清空可能很长的到期队列？

## Prototype

静态原型比较了三种结构：

- A：卡内渐进展开。
- B：完成与巩固双栏。
- C：独立复习回执。

原型覆盖 `silent / normal / strong / loading / error / ready / cached` 七种状态，并检查桌面和 390px
移动端。恢复后的历史审计资产保存在
`../artifacts/review-story-experience.html`，不属于生产代码或待实现 UI。

## Decision

选择 **C：独立复习回执**：

- 原有复习词卡、评分和完成卡保持不变。
- 当天累计达到资格时，在当前复习卡或完成卡下方显示独立、可选的故事回执；仍有到期词不阻止显示。
- 不满足条件时完全静默，不出现禁用按钮或占位说明。
- 不使用弹窗、遮罩、抽屉或新的一级入口。
- AI 只在用户点击后调用。
- loading、error、ready 和 cached 都留在同一回执内。
- 回到词库始终可见；生成失败不影响已经保存的复习结果。
- ready/cached 状态提供“用其中一个词写一句”，进入既有造句、批改和保存流程。

选择 C 是因为它不污染已经成立的完成反馈，同时让加强提醒有独立层级；移动端也不需要把双栏结构
降级成复杂堆叠。

## Out of scope

- 故事历史、收藏、公开、分享。
- 弹窗式强制任务。
- 独立写作编辑器。
- 单词图片；未来视觉实验只考虑由已验证故事派生漫画。
