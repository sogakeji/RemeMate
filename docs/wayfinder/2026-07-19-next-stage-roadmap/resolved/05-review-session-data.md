# 核验复习会话与每日选词数据

## Question

当前模型能否在不新增复习会话表的前提下，稳定得到用户本地日、当前学习语言、当天有效评分词、
评分等级、故事 eligibility、确定性选词和同一输入的缓存身份？

## Resolution

不新增 `ReviewSession`。短故事按用户本地日期和学习语言，从 `ReviewLog` 聚合当天记录：

- 日期边界使用用户时区的本地午夜，再转换为 UTC 半开区间查询。
- 一天内同一个 `word_id` 可能因重试或 lapse 10 分钟回炉产生多条日志，计数必须按 distinct word，
  评分取当天最差等级；原始日志行数不能作为复习词数。
- 只选择仍属于当前用户和当前语言词表的词。
- 当天有效评分词少于 10 且最差等级词不超过 5 时静默；达到 10 时显示普通入口；最差等级词超过
  5 时显示加强入口并覆盖数量下限。
- 目标词按最差等级优先、其次模糊、最后秒记起确定性排序，最多 5 个；不足 3 个时使用全部，
  不从历史随机补词。

缓存使用私有 `review_story_runs`，而不是 Flask cookie session、localStorage 或 `OutputEntry`：

- 身份包含用户、本地日期、目标语言、反馈语言、契约版本和规范化输入哈希。
- 数据库唯一约束保证同一输入只有一条 run；状态机负责 pending、ready、failed 与重试。
- 表必须 FORCE RLS，普通请求只能读取和修改自己的 run。
- 故事正文是短期脚手架，不进入用户输出历史。

日内摘要应由服务层返回不可变的确定性快照，生成路由不得接受客户端传来的任意词 ID 列表。

## Required tests

- 用户时区和跨午夜窗口。
- 同词重复日志、lapse 回炉和当天最差评分。
- 跨语言与跨用户隔离。
- 9/10 个有效词和 5/6 个遗忘词的触发边界。
- 3、4、5 个目标词及不足 3 个词的确定性排序。
- 相同输入哈希稳定，反馈语言或实际输入变化会产生新哈希。
- story run 的 RLS、唯一约束和并发取得行为。
