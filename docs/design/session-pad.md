# SessionPad：双人语言交换复盘信纸

> 记录日期：2026-07-09
> 状态：产品方向已纠偏。B1 语言伙伴基础、B2 复盘信纸 v1 已完成真机验收；
> B3「帮自己记 → 候选词审核」、B4「伙伴邀请与确认绑定」、B5「反馈包快照投递」、
> B6「感谢」、B7「接收内容采纳」与 B8「AI 会后总结」已完成；手动闭环与 AI 增强
> 已通过自动化测试，等待真实语言交换继续验证产品成功标准。
> 取代：2026-06-22 旧版「实时协作输入板 / guest / WebSocket room」方案。

## 一句话定义

SessionPad 是面向双人语言交换的结构化复盘信纸。

用户围绕一位语言伙伴记录「帮自己记」和「帮他记」的学习内容；帮自己记进入自己的候选词、词库和 SRS；帮他记经过筛选后作为快照反馈包推送给对方。AI 只做会后总结增强，不阻塞记录、保存、推送、入库。

## 闭测验证定位

SessionPad 在闭测期不是主线替代品，而是特色吸引力验证。

主线仍是日常复习 + 输出闭环；SessionPad 的闭测目标是验证：用户是否愿意把 RemeMate 带到真实语言交换现场或会后复盘中，并把一次交换沉淀成双方可继续学习的材料。

闭测小切片只追求一个最小闭环：

```text
记录一位语伴 → 写一张复盘信纸 → 选择帮他记的内容 → 发送反馈包 → 对方感谢或采纳
```

如果这个闭环不能打动真实语伴，继续扩展实时协作、AI 总结、复杂关系权限都没有意义。

### 登录与关系要求

闭测验证版要求对方登录 RemeMate 后参与。

原因：

- SessionPad 不是聊天室，没有 guest 免登录的产品必要性。
- 反馈包、感谢、采纳、候选词入库都必须绑定到真实用户关系。
- 未登录访问会让隐私、归属、权限和后续学习链路变模糊。

允许先创建未绑定伙伴档案，但对方要看到反馈包、点击感谢或采纳内容时，必须绑定到真实 RemeMate 账号。

### B4 已实现绑定边界

- 伙伴所有者输入对方的 RemeMate 登录邮箱，生成 7 天有效的邀请链接。
- 生成邀请不查询或显示邮箱是否已经注册，避免账号枚举。
- 邮箱不会出现在链接中；链接令牌只携带不可逆邮箱指纹并由 `SECRET_KEY` 签名。
- 只有对应邮箱的已登录账号能查看和确认邀请，不能绑定自己的账号。
- 每位伙伴只有最新生成的邀请有效；数据库仅保存令牌哈希，新邀请自动作废旧链接。
- 确认操作通过 BYPASSRLS 的窄服务事务完成，并由数据库约束阻止自绑定和同一账号重复绑定。
- 绑定只建立未来反馈包的明确收件关系，不让接收方查看伙伴所有者过去的复盘、私人备注或词库。
- 当前绑定是伙伴档案所有者指向接收账号的已确认关系；接收方自己的伙伴档案不自动创建。

### 闭测成功标准

SessionPad 小切片不以“看起来有趣”作为成功标准，而以真实语言交换后的行为作为标准。

首轮闭测成功标准：

- 至少完成 2-3 次真实语言交换复盘。
- 至少有一次对方点击感谢，或把收到的某条表达 / 修正加入自己的候选词。

失败信号：

- 用户只把它当成自己的会后笔记，对方没有参与。
- 对方看过反馈包但没有感谢、采纳或继续使用。
- 复盘内容无法自然进入候选词、词库、SRS 或下次输出。

若失败信号出现，应先缩小或重构 SessionPad，不继续扩展实时协作、复杂权限、AI 总结或社交功能。

## 核心判断

SessionPad 符合 RemeMate 的长期核心产品逻辑，但不是旧设计里的聊天室、共享房间或协作文档。

它的产品价值不是“多人实时编辑”，而是把真实语言交换中的关系、反馈和表达沉淀成双方各自可复习的学习资产。

RemeMate 已有一条主线：我和语言材料的关系。

- 词库
- 复习
- 造句
- 三行日记
- 阅读收词
- 文本抽词 / CSV 导入

SessionPad 开启第二条主线：我和语言伙伴的关系。

- 语言伙伴
- 复盘信纸
- 帮自己记
- 帮他记
- 反馈包
- 感谢

## 不做什么

首版明确不做：

- 聊天室
- 小组交换
- guest 免登录参与
- 公开分享链接
- 双方共同编辑同一份文档
- WebSocket 实时协作
- 评论 / 回复线程
- 已读 / 忽略等消息压力状态
- 点赞、排行榜、社交动态
- 由 AI 决定是否可保存或推送

这些方向会把产品拉向社交软件或协作文档，偏离 RemeMate 的学习闭环。

## 领域术语

### Language Partner / 语言伙伴

一位与用户进行语言交换的人。语言伙伴可以先是未绑定档案，之后再绑定到真实 RemeMate 用户。

### Unclaimed Partner / 未绑定伙伴

用户先手动创建的伙伴档案，只包含昵称、语言、备注等关系信息。未绑定前，对方看不到任何内容。

### Claimed Partner / 已绑定伙伴

未绑定伙伴与一个真实 RemeMate 账号建立绑定后形成的关系。绑定后仍不会自动暴露历史私密内容。

### SessionPad / 复盘信纸

用户围绕某位语言伙伴创建的一张结构化学习信纸。它可以会中随手写，也可以会后认真整理。

### For Me / 帮自己记

服务于我自己的学习和关系记忆。默认私有。

典型内容：

- 我想记住的词、短语、表达
- 对方教我的自然说法
- 我下次想复习或使用的句子
- 私人伙伴笔记
- 下次想聊的话题

### For Partner / 帮他记

服务于对方学习的内容。可以筛选后推送给对方。

典型内容：

- 值得对方记住的词、短语、表达
- 对方的错误修正
- 给对方的自然说法或例句
- 下次建议练习的表达

### Partner Packet / 反馈包

从我的「帮他记」中筛选并发送给对方的快照副本。反馈包不是同步引用，发送后稳定存在。

### Received Packet / 收到的反馈包

对方发给我的反馈包。我可以感谢，也可以把其中表达或修正加入自己的候选词审核。

### Thank / 感谢

收到反馈包后的轻量礼貌回应。感谢不是评论线程，不制造任务压力，只完成善意闭环。

## 首版产品形态

入口：

```text
我的 → 语言伙伴 → 伙伴详情 → 新建复盘 / 历史复盘
```

结构：

```text
复盘信纸
├── 帮自己记
│   ├── 表达 / 单词
│   ├── 句子 / 自然说法
│   ├── 私人伙伴笔记
│   └── 下次想聊 / 想复习
└── 帮他记
    ├── 表达 / 单词
    ├── 错误修正
    ├── 自然说法 / 例句
    └── 下次建议
```

领域模型仍是 `帮自己记` / `帮他记` 两栏，但交互层不同时平铺两个大输入区。

- 桌面和移动端都先用顶部按钮切换当前记录对象。
- 下方只显示当前侧的一张编辑卡：左侧为四个结构化模块按钮，右侧为大输入区。
- 点击模块按钮直接切换输入类型、标签和提示，不使用下拉菜单。
- 移动端模块按钮排成 2×2；已记录内容跟随当前侧显示。
- 提交后保留当前侧和模块，便于连续记录同类内容。

## 数据所有权

首版不做共同编辑。每个人拥有自己的信纸。

- 我的信纸由我创建、编辑、保存。
- 对方看不到我的原始信纸。
- 我只能从「帮他记」中筛选内容推送给对方。
- 推送后生成反馈包快照。
- 对方收到的是副本，不是我原始信纸的同步引用。
- 我后续修改原始信纸，不影响对方已收到的反馈包。
- 如果需要修正或补充，发送新的补充包。

这个模型保留共享价值，同时避免协作文档的权限复杂度。

### B5 已实现反馈包边界

- 只有已绑定伙伴的复盘可以发送反馈包。
- 发送者在当前复盘中逐条勾选「帮他记」内容；「帮自己记」、其他复盘和其他用户的条目无法混入。
- 发送时复制发送者名称、伙伴名称、交换日期、标题、条目类型和正文；原条目后续修改或删除不影响已发送内容。
- 已发送包是不可更新、不可删除的快照；来源复盘和伙伴档案存在反馈包时不能被级联删除。
- 完全相同的快照重复提交会返回原反馈包，避免双击重复投递；内容或选择变化后可以发送补充包。
- 收件人通过「我的 → 收到的反馈」查看列表和详情，不会获得原复盘、私人伙伴备注或词库访问权。
- `partner_packets` 与 `partner_packet_items` 使用 FORCE RLS：只有发送者和接收者可读，只有发送者可创建，双方都不能修改或删除。
- 伙伴、复盘、发送者和接收者使用复合外键绑定，数据库拒绝向非绑定账号投递。
- B5 只完成选择、快照发送与查看；感谢和采纳留在后续独立切片。

## 隐私规则

默认私有，主动推送。

- `帮自己记` 默认私有。
- 私人伙伴笔记永远默认私有。
- 未绑定伙伴看不到任何内容。
- 伙伴绑定后，也不默认暴露历史记录。
- 共享发生在条目级，而不是整张信纸一刀切。
- 只有被选入反馈包的 `帮他记` 内容会被发送给对方。

绑定关系不是授权对方查看历史私密笔记。绑定只是让未来的反馈包有明确收件人。

## 与词库 / 候选词 / SRS 的关系

`帮自己记` 进入我的学习闭环：

```text
帮自己记 → 候选词审核 → 我的词库 → SRS → 造句 / 日记 / 复习
```

### B3 已实现边界

- 只有「帮自己记」中的词语 / 表达、句子 / 自然说法可以主动加入候选词审核。
- 私人伙伴笔记、下次想聊，以及全部「帮他记」内容不能进入我的词库。
- 系统不调用 AI 拆词或补全，整条记录作为用户确认过的学习表达进入候选审核。
- 同一条记录重复点击不会重复创建候选词；已在生词本中的内容不会再次创建。
- 首次加入时以伙伴母语确定目标语言，并把语言固化在该复盘的 SessionPad 来源中；
  伙伴资料以后修改语言，不会让旧复盘跨词表漂移。
- 伙伴母语必须属于用户「正在学」的语言，否则先引导用户去设置。
- 复盘、来源和候选词之间使用同用户复合外键，服务层和数据库共同阻止跨用户挂接。

`帮他记` 不进入我的词库：

```text
帮他记 → 反馈包 → 对方收到 → 对方决定是否加入自己的候选词审核
```

我不能替对方管理词库。RemeMate 只允许我给对方学习建议，由对方决定是否采纳。

### B7 已实现采纳边界

- 新反馈包在发送时固化伙伴「正在学」的语言；之后修改伙伴资料不会让候选词跨语言漂移。
- 接收方可从表达、自然说法和错误修正中手动整理一个 1-200 字符的词或表达，再加入候选词审核。
- 「下次建议」不能进入候选词；系统不调用 AI 拆词，也不自动接受入库。
- 每个反馈包为接收方复用一个 `sessionpad` intake source，完整反馈正文保存在候选词的 `source_example`。
- 同一反馈条目重复提交幂等；已在生词本中的内容不会重复生成候选词。
- `partner_packet_intakes` 与 `partner_packet_item_adoptions` 只允许接收方读写，发送者看不到对方是否采纳。
- 复合外键把包、条目、接收方、来源和候选词锁在同一用户边界，数据库拒绝跨用户挂接。
- 旧反馈若无法补出语言快照，不展示采纳入口；接收方未把该语言加入「正在学」时先引导去设置。

## 收到反馈包后的动作

首版只做学习处理动作：

- 查看反馈包
- 感谢
- 将表达 / 修正加入自己的候选词审核

首版不做：

- 已读
- 忽略
- 拒绝
- 评论
- 回复线程
- 聊天

这样避免负反馈和消息压力，保持产品气质温和。

### B6 已实现感谢边界

- 只有反馈包接收方可以点击一次「感谢对方」；发送者和第三人不能代为感谢。
- 感谢单独保存在 `partner_packet_thanks`，不修改不可变反馈包。
- 重复点击幂等，始终只有一条感谢记录；感谢不能撤回、修改或转成评论。
- 发送者和接收者都能看到感谢状态，第三人不可见。
- 感谢不产生已读、忽略、评论、回复线程或通知状态。
- 接收方详情固定加载反馈条目与感谢状态，不给收件列表增加逐包查询。

## AI 的角色

SessionPad 手动为主，AI 只做会后复盘增强。

AI 可生成：

- 本 session 的收获
- 讨论深度
- 讨论内容主题词云
- 下次建议
- 从草稿中整理出「帮自己记」和「帮他记」的建议

AI 不可用时：

- 仍可记录
- 仍可保存
- 仍可筛选
- 仍可推送
- 仍可把「帮自己记」加入候选词审核

AI 失败只能影响总结质量，不能阻塞核心流程。

### B8 已实现总结边界

- AI 总结由复盘所有者手动触发；打开或刷新复盘页不会自动调用模型。
- 输入只包含复盘中的学习条目，明确排除「私人伙伴笔记」，也不读取伙伴档案的私人备注。
- 输出使用用户设置的反馈语言，结构固定为本次收获、讨论深度、主题词和下次建议。
- 当前总结以 JSON 快照保存在用户自己的复盘中；条目变化后旧总结仍可查看，但会提示内容已更新。
- 同一内容快照只生成一次；总结仍为最新时重复提交不会再次调用模型或重复记账。
- 过长内容不会静默截断后伪装成完整总结，而是提示用户先整理；AI 不可用或输出无法解析时不写入
  伪总结，也不影响已有信纸。
- 成功调用记录为 `sessionpad_summary` token 用量，但不占用造句批改次数。
- AI 总结仍是手动复盘之后的后置增强，不改变「记录 → 推送 → 感谢 / 采纳」的首要闭环。

## 用户场景

### 会中随手写

我和 Pierre 正在做法语交换。我打开 Pierre 的伙伴页，新建一张复盘信纸。交流中我快速记下：

- 帮自己记：`avoir hâte de`
- 帮他记：中文里「我很同意」更自然可以说「我很赞同」
- 私人伙伴笔记：Pierre 下个月要准备 HSK

会后我筛选「帮他记」的内容，发送一个反馈包给 Pierre。

### 会后誊清

我没有在交流中打开 RemeMate。会后我进入语言伙伴页，新建复盘，把刚才的内容整理成两栏。AI 可以帮我生成总结和下次建议，但我仍手动确认哪些内容入库、哪些内容推给对方。

### 未绑定伙伴

我先创建一个未绑定伙伴 `Pierre`，记录几次交换。Pierre 之后注册 RemeMate，我把这个伙伴档案绑定给他的账号。绑定后，他只能收到我主动发送的反馈包，不能自动看到我的历史私密记录。

## 首版范围

首版做：

- 语言伙伴列表与详情
- 未绑定伙伴档案
- 伙伴绑定到真实用户
- 从伙伴详情新建复盘信纸
- 两栏结构：帮自己记 / 帮他记
- 帮自己记加入我的候选词审核
- 帮他记筛选生成反馈包
- 反馈包快照发送给已绑定伙伴
- 收到反馈包
- 感谢
- 从收到的反馈包加入自己的候选词审核
- AI 会后总结增强，失败不阻塞

首版不做：

- 小组交换
- guest
- 公开链接
- 实时多人编辑
- 评论/回复
- 复杂通知系统
- 语音转录
- 双人实时转录

## 后续分期

### P1：复盘信纸主闭环

目标：验证用户是否愿意围绕语言伙伴记录、推送、采纳学习反馈。

最小闭环：

```text
语言伙伴 → 新建复盘 → 两栏记录 → 帮自己记入候选词 → 帮他记发反馈包 → 对方感谢/采纳
```

### P2：伙伴记忆增强

- 伙伴详情中的历史复盘摘要
- 最近互相推送的反馈包
- 下次建议聚合
- 伙伴相关的已入库词回顾

### P3：AI 复盘增强

- 自动整理草稿
- 更好的讨论深度评估
- 主题词云
- 下次语言交换建议

### P4：语音与现场增强

- 语音转录
- 双人实时转录
- 但仍保持双人信纸模型，不转向小组聊天室

## 关键决策记录

1. SessionPad 不是聊天室，不是 Google Docs，不是共享房间。
2. 首版只做双人语言交换，不做小组。
3. 入口在 `我的 → 语言伙伴 → 复盘`。
4. 可以先记录未绑定伙伴，之后绑定真实 RemeMate 用户。
5. 一人一张信纸，各自拥有，不做共同编辑。
6. 信纸是两栏结构：`帮自己记` / `帮他记`。
7. `帮自己记` 可进入我的候选词和词库。
8. `帮他记` 不进入我的词库，只能筛选推送给对方。
9. 推送生成快照副本，不是同步引用。
10. 收到反馈包后只做学习处理：感谢、加入候选词。
11. 不做已读、忽略、评论、回复线程。
12. AI 手动为主，只做会后总结：收获、讨论深度、主题词云、下次建议。
13. 私人伙伴笔记永远默认私有。

## 对旧方案的取舍

旧方案中的以下内容废弃：

- `session_room`
- guest 免注册加入
- 公开分享链接
- active / ended / expired 房间生命周期
- WebSocket 实时同步
- 双方共同追加同一条目流
- 会后自动跳转 `/extract` 的房间模型

保留并重解释：

- 语言伙伴关系是核心对象。
- 真实对话是重要词汇来源。
- 词汇来源需要能溯源到语言伙伴。
- AI summary 有价值，但只能作为增强。
