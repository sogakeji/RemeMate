# 会话输入板（Session Pad）功能概要

> 记录日期：2026-06-22
> 状态：方向确认，待详细设计（P2/P3 功能）

---

## 一句话定义

语言交换时双方共同打开一个实时协作输入板，随手记录生词和好表达，会话结束后跳转 /extract 各自选词入库，打通"真实对话 → SRS 词库"的闭环。

---

## 解决的核心痛点

语言交换"永远重置"问题：每次见面重新自我介绍，聊过的词没有留存，下次见面没有上下文。Session Pad 让每次会话产生可沉淀的内容。

---

## 功能流程

```
用户 A 创建会话 → 生成链接/二维码
    ↓
用户 B 加入同一会话
    ↓
双方实时看到对方输入的内容（WebSocket 同步）
    ↓
会话结束 → 跳转 /extract
    ↓
各自选择要加入自己词库的词 → SRS 排程
```

---

## 场景优先级

| 场景 | 摩擦度 | 优先级 |
|---|---|---|
| **线上语言交换**（视频通话同时开一个标签）| 低 | **P1 主打** |
| **线下会后回顾**（聊完后一起打开，回忆生词）| 中 | P2 |
| **线下实时输入**（聊天同时低头打字）| 高 | 暂不主推 |

---

## 进化路径

| 阶段 | 内容 | 技术难度 |
|---|---|---|
| **P1** | 协作输入板 + /extract 跳转 | 中（WebSocket 实时同步，Flask + Socket.IO）|
| **P2** | 单人语音转录 + 自动抽词 | 低（Whisper API 成熟）|
| **P3** | 双人实时转录 + 各自抽词 | 高（多说话人识别 diarization + 实时流）—— **真正的市场空白** |

---

## 市场验证

- VoiceLingua（2025）做了单人版：实时转录 + 抽词 + SM-2，验证了方向可行
- 无任何产品做多人协作会话捕捉 + SRS 入库这个组合
- 市场空白确认

---

## 与记搭产品主线的关系

Session Pad 是"遇见人 → 记录对话 → 变成词库 → SRS 复习"这条线的关键环节，直接回应了语言交换社交场景的核心需求，与句子广场、/write 造句日记共同构成"输入 → 沉淀 → 输出"闭环。
